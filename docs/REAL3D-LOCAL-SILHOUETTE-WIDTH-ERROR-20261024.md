# Real3D｜輪廓局部寬窄與左右偏移診斷 V1

## 功能定位

承接已通過 GitHub Source+Browser GPU 的 PR #54（真 OBJ／GLB → 咖啡色 WebGL 七圖 → 四張透明參考 PNG 差異對照）。這輪針對**單一整體 IoU 可能掩蓋局部過寬或過窄**的問題，將原始同一張 1080×1920 的參考遮罩和 GPU 圖分成 12 個固定高度區段，逐段以原始像素計算偏差。此功能不依賴外部 AI、不生成/修改人體幾何、不補網格、不靠炫光。

## 本輪直接量測

每個方向、每個高度區段計算：

- `referenceMeanCoveragePx`：參考 PNG alpha 遮罩的前景像素數 ÷ 本段行數；
- `modelMeanCoveragePx`：GPU 渲染來源的實體前景像素數 ÷ 本段行數；
- `signedCoverageDeltaPx`：GPU 減去參考，正值表示此段影像**平均覆蓋過寬**、負值表示覆蓋不足；若人體手臂分開、空隙很大，這不是實際腰寬或骨盆厚度；
- `signedCoverageDeltaPercent`：以參考平均像素覆蓋為分母；
- `imageCentroidXDeltaPx`：此高度段的 GPU 與參考前景 X 重心相差多少像素，幫助判定向左或右偏；
- `modelExtent` / `referenceExtent`：最左、最右的原生像素位置；
- `worstBandId`：在有足夠參考像素的區段中，平均覆蓋誤差最大的一段。**不是自動的人體錯誤定論**。

工作區新增四方向選擇框及可橫向捲動的 12 段表格，直接使用真像素資料。未取得參考圖、透明背景、方向或尺寸錯誤時不會產生假測量。

## 技術及真實性的界線

- 各高度段依照畫面頂部 0–100% 均分，**沒有**經驗證頭、肩、胸、腰、骨盆、手腳的解剖分界，UI 一律不使用解剖名稱宣稱自動識別。
- 原版黑色 2px 外描邊可能帶來少量像素誤差；此版本正面來源選 `BROWN_FLAT`，側面等選 `BROWN_VOLUME`，任何輸出仍附 SHA。
- 四方向必須原圖正交透視/相機/尺度一致。不能拿一般斜角透視人像直接說是相同的拍攝比例；現有透明背景 1080×1920 PNG 要求保留。
- IoU、像素寬度差及重心偏移屬**外形影像量測**，不保證真人人體自然度、臉部五官、頭頸接合或手指腳趾比例；此類人體 Gate 仍 BLOCK。
- 現有測試素材仍是明確標示為 NONHUMAN 的合成 OBJ／PNG，專門用來驗證功能，絕不能代替真人來源與外觀對照。
- 不更改已核准的咖啡色、黑線、柔和陰影／低高光 V1 順序；使用者提出的多次微凹凸、隙縫漸層仍為後續階段。
- 正式網站 Render、RGB HOME、CNC 3AX～6AX/NC、APK/EXE 不部署，PR 維持 Draft。

## 驗收

1. Node 檢查完全相同的 silhouette bands 0 差、局部額外像素顯示偏寬、缺失像素顯示偏窄、平移顯示 X 重心變動，同時驗證來源陣列不變。
2. Chromium 由真合成 OBJ 本機匯入，生成四個方向 GPU PNG，與四個真正透明 PNG 原像素比較；介面四方向切換均有 12 段真數據；報告存在相同資料。
3. 不得從以上兩項推論人體驗收 PASS、AI 照片自動去背、照片 1:1 或真實動畫。
