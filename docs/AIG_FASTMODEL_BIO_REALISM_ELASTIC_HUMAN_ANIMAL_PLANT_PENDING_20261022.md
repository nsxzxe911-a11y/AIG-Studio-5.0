## 一、研究目的

從目前的技術人體與動畫能力，升級成涵蓋**人類、動物及部分植物**的真實色彩、比例、表面材質、可動結構與彈性變形系統。

必須分離兩種目標，不能混稱完成：

1. **BIO_REALISTIC 生物寫實模式**：色彩、正常比例、不同組織各自的柔韌度與有限延展、自然回彈、非穿模動作。
2. **STYLIZED_ELASTIC 藝術彈性／橡膠模式**：可刻意誇張拉伸、擠壓、扭轉、回彈；必須具可設定形變上限及穩定性保護，不能冒稱符合真實解剖或植物力學。

## 二、共用引擎、分開的生物結構

共用能力：來源與摘要雜湊、3D 座標／比例正規化、可見區域與推估區域標記、材質 PBR 參數、骨架或變形場驅動、軟組織/彈性物理、約束、固定步長、輸出 GLB／影片、逐幀驗收報告。

**絕不把同一套「人形骨架」硬套給動物或植物。**

| 類別 | 形態/運動主導 | 表面與彈性重點 | 首輪可驗證案例 |
| --- | --- | --- | --- |
| 人類 HUMAN | 人體比例、全身骨架、IK、蒙皮 | 不同皮膚區域、關節褶皺、體積保持、臉/肩/肘/膝 | 技術全身、手肘與膝彎、雙臂雙腿動作 |
| 動物 ANIMAL | 物種個別四肢/脊椎/尾巴/耳翼骨架 | 真皮、皮毛、耳朵、尾巴、腹部軟組織 | 貓／狗四足步態 + 耳尾延遲回彈 |
| 植物 PLANT | **分枝圖、連續桿/柔性樑及形變場**，非人形骨骼 | 莖、藤蔓、葉片、花瓣、果肉；隨物種及含水狀態調整剛度、阻尼、延展限制 | 柔性枝葉受風擺動、藤蔓彎曲、花瓣輕微開合、含水變化下垂 |

## 三、植物專用子系統（新增正式範圍）

不要求所有植物都像橡膠。植物在外力、含水、組織類型、尺寸尺度下差異極大；初期以**特定柔性植物與部位**為支援對象。

1. **柔軟葉片**：葉脈／面片方向決定彎曲及扭轉，葉柄固定，葉片隨風振動；邊緣避免大幅破裂與折疊穿透。
2. **花瓣、花冠**：以薄片彎曲及形變目標處理小幅開合、顫動；更大的開花過程是生長形態／時間變化，不偽裝成純彈簧物理。
3. **藤蔓、柔性枝條、草莖**：沿中心線建立節點／桿狀連接，限制曲率與伸長量；可受風、重力與觸碰力驅動並回彈。
4. **柔軟果實／多肉組織**：受擠壓形成局部變形及體積保持，避免形變後厚度歸零或反轉網格。
5. **下垂與恢復**：可模擬水分／膨壓改變造成的*剛度和目標形狀*差異，但不得以單張照片宣稱精準辨識植物生理狀態。
6. **橡膠化藝術模式**：在植物本身組織範圍外允許誇張藤蔓拉長、花瓣回彈、果肉伸縮，但須有明顯模式標示、最大延伸比、碰撞與自交守門。

首波支援建議：**草、藤蔓、柔軟葉片、花瓣、柔軟果實**。木質樹幹的大幅橡膠拉伸不屬於寫實模式。

## 四、色彩與幾何

- 色彩以來源照片或受控材質參考為基準，區分 base color、光照、粗糙度、半透明/次表面外觀；人皮、動物毛皮、葉面／花瓣／果皮不可共用單一塑膠 shader。
- 使用一致色彩空間及輸入/輸出轉換；保留未改動照片及其 SHA，避免反覆校色污染來源。
- 人、動物、植物分開建立形態先驗和尺度基準；單張照片中的遮擋、鏡頭焦距、未拍到背面必須標註「推估」，不宣稱與實物完全一致。
- 渲染網格與變形求解網格可分開；不要每幀重建超高密度網格，採局部 LOD、權重或低維變形映射。

## 五、動力學設計

- 起點：現有骨架蒙皮技術不得撤除；在人／動物增加 corrective shapes、局部柔性與關節區域限制。
- 植物走枝條圖／梁／薄片的獨立求解器；不將植物葉脈映射成人體肢體。
- 固定物理子步長、可重現隨機種子、重力、風場、阻尼、剛度、應變上限與回彈；遇非有限頂點、自交或應變超界立即隔離該動畫計算，不清空其他資產。
- 「真實模式」採組織個別的有限彈性參數；「橡膠模式」另有可控的 stretch/squash、體積維持、速度上限及形變安全閥。
- 實測前所有物理及皮膚/植物材料係數都是**待校正假設值**，不得暗示已由實驗或生理測量證實。

## 六、正式施工順序（此文件只排程、不啟動施工）

### Phase R1：基礎幾何、比例及真實材質
- 建立 human/animal/plant 類型 contract、物種/區域標籤、可見與推估區域、真實色彩參考及 PBR 參數。
- 真圖片 → 可重現幾何／模型；不能僅以靜態 RGB 圖或相機位移表示建模成功。

### Phase R2：人類真實皮膚彈性
- 在技術 17 骨 GLB 基礎先做可重現 skinning + corrective deformations，再加軟組織延遲、體積及上限驗證。
- 正式女主角的照片一致性與全身真實比例另立 Gate，不因技術人體 PASS 放行。

### Phase R3：動物專用體型／骨架與皮毛
- 先驗證單一物種的四足骨架、皮毛分層、走／跑過程及耳尾物理；再擴物種。

### Phase R4：植物柔性引擎
- 草莖/藤蔓連續桿、葉面薄片、花瓣、果肉各用相應變形模型。
- 先用可控施力與風場正負測試；再做生長和含水下垂的時間控制。

### Phase R5：可控橡膠化模式
- 在各生物原本模式成功後，加入最大伸長率、碰撞、形變場、回彈與誇張動畫參數。
- 禁止以藝術模式 PASS 冒充真實生物運動。

### Phase R6：控制、配對、正式 RGB UI
- 僅在各來源核心與反向驗證 PASS 後建立 Button ID / Command ID / callback → Engine → 真 GLB／影格／檔案。
- Android／Windows／正式 Web 分平台截圖、影片解碼、FPS 與記憶體驗證。工程殼不得成正式主畫面。

## 七、必須有的測試與 Release Gate

每項核心至少有正向與負向測試，而且回歸不得破壞已通過的 2D/2.5D、真 GLB、聲音、錄影、CAD/CAM/NC：

- **比例/相貌**：檢查解剖或植物結構約束、關節覆蓋、來源影像 SHA、一致性及遮擋推估標記。
- **皮膚/組織**：逐影格實際蒙皮頂點位移；有限法線、三角形面積、最小厚度、應變與回彈曲線；關節處不斷裂。
- **植物**：葉柄固定與葉緣彎曲量；藤蔓曲率上限、果肉壓縮體積、花瓣回復軌跡；無 NaN/Inf、網格翻面、根部脫節或爆炸。
- **彈性**：指定施力 → 明確位移 → 撤力後有阻尼回復；真實／橡膠模式分別驗證，並紀錄測試參數。
- **時間穩定**：至少 30Hz 逐幀網格檢查；影格真正不同、不是攝影機移動；動畫結束和來源切換不遺失已驗證產物。
- **實際輸出**：可載入帶蒙皮或植物變形的 GLB／其他明確格式；1080p 影片要能解碼並觀察變形，輸出檔有 digest。
- **效能**：Android + Windows 分開測 FPS、CPU/GPU、記憶體、溫度與關閉光追的 fallback；不能靠理論值宣稱 60 FPS。
- **權威 UI**：正式 RGB 已核准圖／樣式獨立；真 Button ID、真 callback、真狀態及來源 SHA。
- **失敗狀態**：缺少實物參考或合適物種模型時回 `BLOCKED/NOT_TESTED`，不得捏造已完成的照片身份、真實植物材料係數或無限橡膠伸長。
