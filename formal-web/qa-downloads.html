怎麼真正省下 GitHub Actions 配額？

網站應當做版本目錄與快速下載入口；APK／EXE 檔案則放在有保留期限、完整性與存取控制的持久物件儲存或經標記的 QA prerelease 資產。只有實際完成二進位檔上傳、從新位置重新下載並驗證 SHA-256，才將連結改成「AIG 網站可直接下載」。

  • 測試日常：不要每次都上傳 APK／JAR／EXE；只保存來源 SHA、core/UI Gate、失敗證據與必要 log。
  • 頁面驗收與可用交付：才生成 APK／Windows EXE；QA 產物與正式 Release 獨立。
  • 正式檔案：以可驗證 SHA、簽章、實際啟動圖、CAD→CAM→SIM→NC 及 3～6AX 安全為放行條件。
  • Render 靜態網站不會自動編譯 Android／Windows，也不等於持久二進位檔倉庫。
