## 真實 GLB 工作流程
1. 由 5.0 本機 GLB 輸入觸發 `parseRiggedGLB` 和 SHA-256；只有 `STRUCTURAL_QA_PASS_ONLY` 的相同來源才讓 5.1 按鈕啟用。
2. 用 **真 Skeleton + Skinning**、`AnimationMixer`、`getVertexPosition` 取得每一動畫 Clip 的實際蒙皮姿態。預設最多三段 Clip，每段五個取樣點（0%、25%、50%、75%、100%）；`5.1` 使用的是 **離散樣本**，不是無限連續幀碰撞。
3. 從真 indexed triangle 中找出四個骨骼權重交界：胸／頸、頸／頭、胸／左上臂、胸／右上臂。以動作起始姿態面積為基準，拒絕面積比小於 0.2 的塌陷或大於 5 的過伸。沒有可驗證交界或缺失骨骼權重會拒絕。
4. 從原始 GLB 中識別名稱含 `ponytail`、`hair`、`braid` 或中文「髮」「馬尾」的獨立髮束 Mesh。缺少命名的髮束時明確 BLOCK，不推測、也不偽造頭髮。
5. 在每個真動畫姿態，取三角面世界座標，使用 **有預算上限的空間格子粗測 + 真三角面分離軸 SAT 細測**；任何確認與身體接觸都標記風險且阻擋，單幀資料過多則拒絕，不把「未完成掃描」偽裝成無穿模。
6. RGB 工作頁新 Button IDs：`aig51-run`、`aig51-report`、`aig51-status`，結果可下載 JSON，包含來源 SHA、每段每個姿態接縫面數、面積比例、接觸三角組與風險紀錄。上一個來源一旦變更，所有舊 5.1 結果失效。

## Gate 的真實意義
- `POSED_GEOMETRY_QA_PASS_ONLY` 只表示提供來源在 **已取樣時刻、且已識別的髮束網格**中，並無本程序確認的三角面碰撞或超限塌陷。沒有真實 5.0 驗證來源即不能判 PASS。
- 髮絲透明 alpha、物理擺動、兩個取樣點之間的快速穿模、衣裙穿插、織物碰撞、自交、臉部照片還原及情感動作 **未驗證**。
- 正式女主角來源 GLB **尚無可驗證的通過證據**；5.1 合成測試建立真 Three.js Bone、Skeleton、SkinnedMesh，但絕不當作使用者批准的人物。
- 60 FPS（Android + Windows）、真機動畫畫面、Render 網站 LIVE、APK / EXE 都未經本輪證實。
- 本階不會自動修改或焊接人物網格，也不會刪舊 GLB。
- source GitHub Gate 成功不代表部署成功。

## 失敗處理
- 無 5.0 PASS、SHA 不同、沒髮束、沒有共享肩頸索引面、不可用的幾何／索引、超出效能預算 -> BLOCKED。
- 動作中肩頸縫邊塌陷或真三角面相交 -> `outcome:'BLOCKED'` + 完整風險 JSON。
- 不覆蓋原人物、舊錄影素材或劇情／聲音系統。

## 回歸測試
- 使用 **非正式人物合成網格**：真三角連通的 15 骨架人體 + 真 quaternion 動作 + 獨立馬尾三角網格；驗證無碰撞的通過、真相交攔截、來源 SHA 不符、缺髮束、取樣預算與 UI 真按鈕。
- 必須等本版最新 SHA 的 GitHub Actions 完整 PASS 才能說來源 Gate 通過。
