## 二、程式升級
`prepared_input.py` accepts a prepared RGBA PNG only if:
1. Original file bytes SHA match exact pinned heroine JPEG; original's actual file format and dimensions are JPEG 1152×1536;
2. Transparent PNG source has exactly the same dimensions, alpha coverage in allowed range, and a meaningful transparent background;
3. Pixels where alpha >=245 are identical to original photo RGB (<=2 LSB difference). Synthesized face/clothing RGB altered inside the foreground is rejected;
4. Combined source chain preserves both `source-original.jpg` and `source-upload.png`, independent SHA and a fail-closed `preparedForegroundEvidence` record.

The original-only, local offline GLB and source review flows are unchanged. The user chooses optional transparent PNG via `#prepared-foreground` and explicitly clicks Generate. Only after all server-side validation does the existing paid Meshy image-to-3D → rigging → animation mechanism submit anything; it never auto-submits from this Draft or ChatGPT. Source journal fingerprint includes candidate SHA to prevent incorrect recovery mixing. The default provider submission runs on prepared transparent `source-upload.png` when the optional input is supplied; provenance still contains the untouched original JPEG exact SHA.

New tests under `tests/test_prepared_input.py`, existing `tests/test_pipeline.py`, and `tests/prepared-foreground-3-8.test.mjs` cover both safe synthetic integration and negative cases. No fee-bearing requests were made to create these code changes or handoff files.
