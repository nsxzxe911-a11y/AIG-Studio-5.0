## 新功能如何真正運作
1. 使用現有 **6.0 照片檔案 SHA-256 及 5.4/5.9 同源檢查**，照片未匹配即不提供掃描。
2. 點「6.1 本機快速掃描」，在原照片 Canvas 點**額頭與下巴**兩點。AIG 以這兩點限制一個臉部搜尋區，避免掃描整張櫻花校園背景時誤挑其他人物。
3. 新 `aig-face-scan-assist-6-1.mjs` 直接讀 Canvas 的 `getImageData` **真 RGBA 像素**，用亮度／周圍亮度差，在左右眼預期的各自搜尋範圍找高對比特徵；對鼻與嘴亦作局部暗亮對比搜尋，不呼叫 Meshy、臉部雲 API、外部人臉模型或任何付費點數。
4. 搜尋結果須先符合 6.0 真照片比例規則：左眼/右眼順序、雙眼水平差、額頭→眼→鼻→嘴→下巴有效長度、橫向偏移限制。**眼部對比不足、手動額頭下巴選錯、五官幾何不合理**時 BLOCK，提示改用 6.0 完整手動六點；不允許回填平均臉、硬湊來源 SHA 或自動批准。
5. 將六點候選以顏色圓點標在 **真原始照片**上。使用者可以選擇某個標記，點照片真正位置個別修正。全部檢視後必須再按「已逐點確認六點」，才會將資料輸送給現有 `calibrateAIG60FaceMarks` 與 `fitAIG60MeasuredFaceGLB`。未確認時 `aig60-build` 保持 disabled。
6. 接受時會再次重讀目前選取的來源照片 bytes 並核對 SHA；接受審核中如果換圖、修正點位或來源變更，過期操作被 revision counter 攔截。
7. 6.0 真 GLB 更新後，原身體／制服／馬尾三角面及真動畫不會因 6.1 被覆蓋。6.0 JSON 新欄位記錄 `candidateAssistant61UserReview`，包含來源 SHA、算法候選信心、人工修正清單與人工確認狀態；仍 `releaseAllowed:false`。
8. 6.0 原本全部六點手動標註保留，手機橫/直向 Canvas 比例坐標仍取實際原照片像素而不是畫面 CSS 像素。

## 風險與 BLOCK 語意
- 6.1 是 **來源像素局部高對比特徵的啟發式輔助定位**，不是訓練好的臉部辨識模型，也未實測任何人臉定位資料集的準確率；髮絲、眉毛、陰影、口紅、臉部表情可能被誤判為眼鼻嘴。畫面「候選點」從來不等於「已驗證人臉」。
- 即使人工確認六點，只對應使用者目視採納的來源 2D 坐標，仍不能據此證明 3D 頭部深度、人物身份、照片神似程度、背面、臉部微表情與嘴型。
- 六點標記採用原照片整體 SHA 的必要條件，修改／重壓縮／裁切都不會冒充原始女主角 Authority。
- 6.1 無法證明 6.0 動畫連續時間零穿模、Android/Windows 原生 60 FPS、1080p 影片已生成或 Render 網站更新；核心相關 Gate 持續獨立。
- 維持原規則：沒有確切證據 → BLOCK；不能把合成照片單元測試宣稱為已拍攝原使用者女主角。
